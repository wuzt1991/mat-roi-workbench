# 新版定价工作台交互原型

> 此文为旧版原型记录。当前以 [v3 修订说明](pricing-prototype-v3.md) 为准，已恢复广告计划并升级尺寸/伪亚麻复核。

更新：2026-09-17。入口：`public/pricing-prototype.html`。

## 预览

在 roi-workbench 目录执行：

```sh
python3 -m http.server 4189 --bind 127.0.0.1 --directory public
```

打开 http://127.0.0.1:4189/pricing-prototype.html 。原型使用独立的浏览器存储键 `mat-pricing-prototype-v1`，不会调用正式工作台数据库 API。首次展示可编辑示例，第二家店铺为空白表。

建议体验：先编辑面积递增策略，再回到 SKU 页观察价格；将某行切换手动售价后修改扣点；在商品转表中载入多材质示例并逐 SKU 选择材质。

## 最新功能落点

| 功能 | 原型行为 |
| --- | --- |
| 删除计划 | 主工作区不再有计划管理，每店一张测算表；旧计划仅在只读归档中出现 |
| 规格组合 | 只限定成本排名范围，不关联商品 ID；同店各组订单占比统一合计 100% |
| 逐 SKU 材质与策略 | 独立行 ID 支持同尺寸不同材质；单行策略优先于组合策略 |
| 固定毛利 | 所有规格使用一个目标毛利率 |
| 成本排名 | 材料成本＋单次运费排序，同成本同档；手动价参与排名；组内缺失成本暂停该组排名定价 |
| 面积递增 | 固定基准＋连续面积增量＋毛利上限；低于基准保持基准毛利，不因增删其他规格改变基准 |
| 毛利率 | （售价－材料－运费）÷售价－平台扣点－税点，分别显示目标和实际值 |
| 售价 | 按目标毛利反推；向上到分、整数元或 .9 元；无效分母和零成本不自动生成售价 |
| 手动覆盖 | 手动售价保持，实际毛利联动；恢复自动后按最新策略计算 |
| ROI | 复用既有退款计算模型，逐行计算后按订单占比汇总；不平均各行 ROI |
| 参数分离 | 订单占比或退款参数异常阻止汇总入账，但不抹掉已算出的有效售价 |
| 商品转表 | 商品名与规格名合并判断材质；零命中或多个材质需人工确认；勾选批量只影响选中行 |
| 材料词匹配 | 别名归一化与最长词消费，避免将冰丝水洗底同时当作冰丝；多材质不自动择一 |
| 厚度 | 材质确定后，规格名中明确的厚度优先于商品标题列举的厚度 |
| Excel 输出 | 29 列纯静态值，保留 ERP 售价和 ID；按模板样式创建新表，清除共享公式影响 |
| 公共资料 | 材料/厚度/成本/重量系数、矩形和异形尺寸、内置常规运费及可编辑固定运费 |
| 店铺日账 | 快照冻结逐行依赖；同店同日禁止重复；更正沿用原快照，原版本标记已更正；支持作废 |
| 旧数据归档 | 导入旧 JSON / Excel，保留原计划和账目；新店铺空白起步，不合并旧规格；相同备份不重复归档 |
| 备份恢复 | 新原型 JSON 完整替换；替换前保存恢复点；冻结金额与快照重算不一致时拒绝导入 |
| 本地冲突 | 多窗口存储变化时停止写入，允许导出本页草稿后重载 |

## 已验证与修复的冲突

1. 旧材料规则 ID 带小数点：新校验器允许现有合法 ID，避免保存失败。
2. 同尺寸多材质：行独立标识，避免编辑一行误改另一行。
3. 定价和 ROI 口径不同：定价只使用单次发货运费，退款影响留在 ROI 模型。
4. 占比异常和售价计算互相阻塞：区分定价异常与汇总异常。
5. 低于模板原行数时共享公式导致 Excel 输出失败：新工作簿仅复制样式与静态值。
6. 同商品材质一致性约束：新版逐 SKU 复核，解除旧版材质冲突限制。
7. 标题多个厚度造成重量/成本取错：使用规格中的明确厚度优先。
8. 移动端隐藏表头文本逃出滚动区域：为表格滚动区设置定位上下文，避免整页横向溢出。
9. 实际毛利浮点误差误报低于目标：比较统一使用容差。
10. 解析/导出期间继续修改转表数据：处理期间禁用复核界面，完成后恢复。
11. 备份只校验历史结果存在：改为使用快照依赖重算校验，拒绝篡改金额或损坏快照。

## 原型边界

这是可操作的新版原型，不是正式桌面版升级包。正式 SQLite 数据迁移、生产版跨电脑备份合并、旧账目的更正/作废仍由原正式工作台处理；原型提供旧数据只读归档与原始导出。新日账汇总与旧归档分开展示，避免口径混合；旧账目占用同店同日期时阻止重复新记。

原型草稿受浏览器存储空间限制，保存失败会保留内存输入并明确提示，不能宣称已保存。策略和账目可导出 JSON 留存。ERP 文件及复核结果仅保留在当前页面会话，刷新后需要重新导入。

当前测试覆盖上述业务与兼容边界，不能证明不存在任何未知 bug；没有验证 Windows 原生运行或正式数据库升级。
