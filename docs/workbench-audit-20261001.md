## 已修复缺陷

### 1. 启动草稿恢复走错保存通道

启动时点击恢复草稿，原实现把 `restore` 作为普通 SaveQueue 保存原因。队列明确拒绝这个原因，可能出现界面内存已改而恢复未落库的情况。

修复：复用专用 `/api/restore` 流程，先暂停并刷新保存队列，携带修订号和稳定操作编号提交恢复，成功后重新读取工作区，再删除对应草稿缓存。失败保留草稿，重试沿用同一操作编号。

验证：模拟首次连接失败；以及真实 HTTP/SQLite 中“服务器已提交、客户端丢失响应”的情形。重试只恢复一次，修订号和存储代次各增加一次，恢复前快照保留。

位置：`public/app.js`；`test/workbench-audit-20261001.test.cjs`。

### 2. 无效数字会把原值清空并保存

原数字读取函数将超限值转换为空字符串，同时清空输入框。由于部分字段允许空白，售价、广告消耗等原有数值会被空白覆盖。

修复：保留原输入，将无效值交给已有校验；浏览器 `badInput` 视作无效数值，不能误当主动清空。校验失败不改工作区、不提交保存；用户明确清空字段的行为仍保留。

验证：售价、广告消耗、退款率的超限值、无穷大及浏览器无效数字；修正后正常保存；主动清空仍生效。重量弹窗覆盖负值、无穷大和超大克数。浏览器实测广告消耗原值为 125 时输入 `1000000000001`，错误输入保留且数据库仍为 125。

位置：`public/app.js`；`test/workbench-audit-20261001.test.cjs`。

### 3. 重量编辑草稿无法恢复

重量弹窗会记录草稿，但恢复类型白名单遗漏 `weight`，导致有草稿却提示类型不可恢复。

修复：补齐类型白名单，沿用 SKU 身份校验。原 SKU 已不存在时不得将旧草稿应用到别的商品。

验证：恢复 321 g 的草稿时弹窗正确重开，确认保存前商品重量不变；已删除 SKU 的草稿被阻止。

位置：`public/app.js`；`test/workbench-audit-20261001.test.cjs`。

### 4. 合法的小数退款率被入账校验误拒绝

试算允许数值计算误差，但入账使用严格比较，出现试算有效、入账失败。例如 `0.01 + 64.04 + 35.95` 在浮点计算中可能为 `100.00000000000001`；`0.01 + 0.06` 也可能略小于 `0.07`。

修复：入账合计和 1 小时退款子集比较沿用领域模型的 `1e-9` 容差。未修改利润公式或重算历史记录。

验证：上述两组合法边界均可入账、备份校验通过；合计 100.01% 或子集真正大于合计的输入仍拒绝。

位置：`public/operating-records/entries.js`；`test/workbench-audit-20261001.test.cjs`。

### 5. 上传被拒绝后残留临时文件

文件流写入完成后，若工作区代次变化或另一个文件任务启动，最终校验会拒绝上传，但原实现只在流传输失败时删除临时文件。备份上传在任务启动被拒绝、文件名解码失败时也会遗留目录。重复操作可能累积磁盘占用。

修复：源文件上传全过程以 `finally` 清理当前 `.part`；辅助任务未成功启动时清理本次目录；任务已占用时，在分配导出目录前拒绝。已启动的正常任务产物继续保留供下载。

验证：上传中途改变工作区代次、制造任务占用、备份文件名解码失败；拒绝后无本次临时文件残留，原源文件和会话元数据不变。真实 HTTP + 子进程验证正常备份导出/读取、上架价格导出和商品源文件上传仍成功。

位置：`server/file-service.cjs`；`test/file-service-lifecycle.test.cjs`；`test/workbench-audit-20261001.test.cjs`。

## 测试误报修正

`test/units-columns.test.js` 原来检查所有可见单元格不得包含 `kg`，因此随机生成的合法记录编号一旦包含这两个字符就会偶发失败。这不代表产品把重量显示成公斤。

用 `record-kg-unit-check` 固定编号复现后，将检查限定到单位表头和程序生成的运费说明，保留克数换算、原始编号不变和完整备份恢复的断言。未为通过测试修改业务数据或导出逻辑。
