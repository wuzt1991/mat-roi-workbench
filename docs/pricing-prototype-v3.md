# 广告计划与转表复核原型 v3

日期：2026-09-17。入口保持 `public/pricing-prototype.html`。此文替代 v2 中“每店只有一张测算表”的设计。

## 预览与操作

```sh
python3 -m http.server 4189 --bind 127.0.0.1 --directory public
```

打开 http://127.0.0.1:4189/pricing-prototype.html 。侧栏选择店铺、广告计划，可以新增、重命名或复制计划；复制时保留规格和费用规则，清空消耗及支付 ROI，避免把原计划投放数据重复计入汇总。

- 计划测算：GMV（含退款）、退款金额、退款后 GMV、退款后投产比、消耗、保本 ROI、盈亏、总投入，全部为预估。
- 店铺总览：比较本店各计划；金额求和后计算投产比，不平均 ROI。计划数据不完整时不生成虚假的完整汇总。
- 计划账本与趋势：按计划、日期筛选，只有有效日账参与金额汇总；导出保留计划列和所有 GMV 口径。
- 商品转表：点击“试用多材质示例”体验型号噪音、伪亚麻、多尺寸和无尺寸四类情况。

## 口径与归属

支付 GMV = 广告消耗 × 支付 ROI。

退款金额 = 支付 GMV ×（未发货退款率＋已发货仅退款率＋退货退款率）。

退款后 GMV = 支付 GMV − 退款金额。

退款后投产比 = 退款后 GMV ÷ 广告消耗；消耗为零显示“—”。1 小时内退款是三类退款的子集，不重复扣减。沿用的净保本 ROI 单独说明，不用作退款后投产比。

SKU 占比、组合、费用、投放参数归属广告计划，日账唯一范围是计划＋日期。不同计划可以同日独立入账。组合成本排名不跨计划；固定毛利、面积递增、手动价覆盖仍遵循已确认的规则。公共策略变动只更新自动定价行，账目使用冻结参数。

所有数据都是预估，不新增实际逐单结算或实时实绩模式。GMV 仅依赖投放和退款参数，SKU 占比未完善不会抹掉可用的 GMV 预估，但会阻止成本/利润汇总和入账。

## 转表识别

### 材质

在普通关键词匹配前检测商品名称及规格名称中的“伪亚麻”。遇到此词始终要求人工选择硅藻泥或亚麻，即使名称中同时有明确的这两种材质名称。其他近似词不自动加入特殊规则。

商品名及原规格保留。逐行选择或勾选批量选择只作用于指定行；若批量给伪亚麻行选了其他材质，整个操作拒绝并保留原状态。后续尺寸修正保留人工材质和确认来源。

### 尺寸

先收集有乘号的完整二维表达式，再进行单位换算和候选去重，不再抓前两个数字拼长宽，不把型号中的连字符当乘号。

| 输入 | 结果 |
| --- | --- |
| MZJ90-3;40*60cm | 40×60cm，0.24㎡ |
| MZJ90-4;50*80cm | 50×80cm，0.40㎡ |
| 400mm×60cm | 40×60cm |
| 40*60cm / 400*600mm | 换算相同，唯一候选 |
| 40*60cm / 50*80cm | 两个候选，人工选择 |
| 编号123 3mm 红色 | 无可靠尺寸，人工填写 |
| 40-60、40至60、ABC40X60、40*60*3mm | 不作为可靠二维尺寸自动采用 |

明确无单位的乘号表达式默认厘米。复核弹窗展示原名称、候选和命中片段，选择候选后填入长宽，也允许手动输入。

材质、尺寸分别维护确认状态。只确认一个不会解除另一个的异常；缺失尺寸时面积、重量、成本不生成有效值。全部异常解决后才允许导出。ERP 售价、商品及规格 ID 保持原值，重量和成本使用实际确认的材质规则。

## 数据迁移和兼容

- 继续使用独立浏览器存储键 `mat-pricing-prototype-v1`，内部结构升级为 `pricing-prototype-2`；不调用正式工作台数据库 API。
- 每个旧原型店铺表迁为一个默认广告计划，保留原规格、费用与投放参数。
- 自动迁移前将原始草稿保存在 `mat-pricing-prototype-v1-before-plan-migration`；完整校验成功才保存新版。
- 原日账只补充计划归属和快照版本标识，不改写原 result 或 frame。旧快照继续按 v1 计算校验；新快照冻结计划及全部依赖。
- 更正旧记录生成 v2 快照，原记录版本保留。迁移可重复执行，不重复生成计划。
- 原型 JSON 备份支持新版与旧原型自动迁移；正式旧 JSON / Excel 继续只读归档。导入不自动合并旧业务计划与广告数据。
- 完整替换前保留恢复点，多窗口冲突停止写入。原型重置不会影响正式数据。

## 边界

此交付仍是可操作原型，不是正式桌面应用升级包；正式数据库迁移、正式跨电脑合并与真实平台数据同步未接入。原型账本不把只读正式旧归档重复计入新计划汇总。

保守识别会把不能可靠判断的尺寸留给人工，尤其型号嵌入、三维尺寸和多规格套装。测试覆盖明确的业务与回归场景，不能据此承诺没有任何未知 bug。
