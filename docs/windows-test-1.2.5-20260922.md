## 已确认问题：重算偶发失败

- 触发：商品转表修改可复用规则后重新计算，父进程与文件子进程在短时间内打开/关闭同一 SQLite 会话库。
- Windows Node 24.21.0：100 次测试、同时运行 4 个隔离测试进程，其中 6 次重算失败，编号 7、38、50、62、71、94。这是测试负载下的比例，不代表日常发生率。
- 错误：`ERR_SQLITE_ERROR` / SQLite 错误码 5 / `database is locked`。堆栈定位 `server/import-session-store.cjs:22`，从 `server/file-job-child.cjs:46` 的重算构造过程进入。
- 原因：构造函数先执行 `PRAGMA journal_mode=WAL` 等语句，之后才执行 `PRAGMA busy_timeout=5000`。数据库刚打开遇到短暂锁冲突时，等待策略还没有生效。
- 隔离验证：保持数据库被占用 400 ms，原顺序在 0 ms 立即失败；仅在测试进程中提前设置 busy timeout，同一构造过程等待约 511 ms 后通过。同一实验在本机已安装的 1.2.5 包内代码、Electron 的 Node 24.18.0 中也得到相同结果；只操作临时数据库，未修改运行源码。
- 待修复：在任何需要访问数据库的初始化语句之前设置锁等待，并确保初始化异常关闭连接；补充确定性的锁竞争回归，复跑 Windows 并发测试及安装产物检查。此次仅记录，尚未落地生产修复。
