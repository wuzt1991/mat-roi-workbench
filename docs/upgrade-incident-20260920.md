# v1.2.0 旧账升级失败修复

2026-09-21 延续修订：旧账兼容修复已纳入 1.2.2 内测范围，与尺寸、销售和转表新功能一并复验。用用户只读真实格式 3 备份及最终包验证迁移、原文恢复点与 11 条历史账目不变；验收结果及本机新备份见 [交付记录](release-1.2.2-internal.md)。旧 1.2.1 结果保留为历史记录，不代替本次复验。Windows 升级脚本现区分旧版 GitHub 与新版 OSS 地址，但本次没有 Windows 原生运行证据。

状态：已构建本地 v1.2.1 Windows x64 安装包，并替换本机 macOS 应用。372 项测试、真实备份和包内源码验证通过；本轮未执行 Windows 实机升级验证，未推送或发布。已发布的 v1.2.0 仍包含此问题。

## 原因与复现

用户提供的 Excel 完整备份为 `MAT-ROI-XLSX` 格式 3，内部工作区版本 3。文件 44059 bytes，SHA-256 为 `04393436d4f81d7970b92709b6d7b469e4d8868bcea275938a8d0f0369853822`。其中有 4 个店铺、10 个计划、70 条商品规格、14 种材料、32 个尺寸和 11 条历史账目。原文件只读，商业数据没有加入版本库或 CI。

第一条早期历史账目缺少 `netMargin`、`netRoi`、`netRevenue`，其余 10 条具有这些字段。旧版模型校验通过，所有已有历史结果与其冻结快照重新计算一致。v1.2.0 的 `validRecordResults` 却要求所有账目都具备后来新增的三个净指标，导致 `migrate` 抛出“旧备份未通过检查”。Store 将异常转为 `INVALID_WORKSPACE`，升级事务回滚，前端显示“工作区升级或校验失败”。Excel 导入路径也在同一迁移函数失败。

原 Windows 升级验证只保存了店铺名称，没有混合年代的账目，未覆盖此场景。

## 修复边界

- 无 `calculationVersion` 的旧版冻结快照允许上述三个净指标不存在。字段存在时仍检查其数值与冻结快照一致。
- 其他历史金额字段仍必须齐全，所有已保存的核心结果继续校验。
- `calculationVersion: 4` 的新账目继续要求全部结果字段，不适用旧版例外。
- 不补写、重算覆盖或删除历史结果及冻结快照，不关闭工作区校验。升级前的原始工作区仍以原文 checkpoint 保留。
- 恢复页面改用现有主题的背景与文字变量，修复深色主题下白底浅色文字及启动布局问题。
- Windows 升级脚本改用旧版安装程序中的真实模型生成两条合成账目（一条无三个净指标，一条完整），经旧客户端保存后升级，并逐字比较升级前后的账目 JSON。此扩展尚待 Windows 实际运行。

## 验证证据

新增四项回归先在未修复代码下全部失败，修复后通过：

1. 混合年代账目从旧数据库升级，checkpoint 原文完整，普通保存和重新打开后历史内容不变。
2. 格式 3 Excel 导入后可再导出为新版备份并完整恢复；修改可见历史金额仍被拒绝。
3. 缺少核心字段、篡改已存净指标或历史快照仍无法通过校验。
4. 旧账更正保留原快照和结果；新账缺少任何净指标仍被拒绝。

本地完整测试 361/361 通过，`npm run check` 与 `git diff --check` 通过。

真实备份的可见工作表与隐藏恢复数据通过正式导入校验；模拟 SQLite 直接升级、查看总账、界面刷新、保存和数据库重新打开均通过。11 条历史账目和总账合计保持不变，70 条规格的尺寸、售价、占比和重量值保持不变。原 Excel 文件校验值未变。

恢复页面在 1440 px 和 390 px 宽度下，两种现有主题无横向溢出，截图已检查。深色正文与背景对比度约 7.30:1。验证 JSON 与截图位于项目外层 `outputs/recovery-20260920/`，不随发布打包。

## 同批深色界面修订

总账的趋势图、汇总卡片和历史详情曾沿用浅色底与深色文字；销售导入的独立弹窗也未接入深色主题。现用原有侧光主题变量补齐这些区域，并覆盖规格与材料编辑、指标显示、入账、商品转表、导出范围、恢复预览、空白与错误状态。改动只在 `data-ui-material="rays"` 下生效；日间模式的原有样式保留。

在隔离的合成工作区中，通过真实浏览器逐项打开页面和弹窗。总账在空白、有账目、1440 px 与 842 px 下测得目标文字最小对比度 7.26:1；完整工作台逐页扫描了 33 个视图或弹窗状态，销售导入与商品转表又扫描了 14 个上传、复核、筛选、批量和错误状态，另核对投放图表、历史账本及重量弹窗 3 个状态。扫描结果没有白色大面板或低于 4.5:1 的可见正文；每个状态与发布版的日间计算样式逐项比较一致。前端无脚本异常，验证期间业务数据原文未变。截图和逐状态报告位于项目外层的 `outputs/ledger-theme-20260920/`、`outputs/all-theme-20260920/`、`outputs/import-theme-20260920/` 和 `outputs/deep-theme-20260920/`，不随发布打包。

需要以新的补丁版本构建 Windows 候选，执行完整候选工作流后再发布；不能覆盖已发布 v1.2.0 的附件。恢复页目前没有正常工作台的更新入口，已停在该页面的用户应使用新补丁安装包覆盖安装，保留现有数据目录。修复后的首次启动会重新迁移原数据库；只有原数据库不在时才使用这份完整备份恢复。
