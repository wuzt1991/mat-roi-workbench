## 4. 数据结构和最小实现边界

继续使用原生 JS、SQLite、SaveQueue 和既有弹窗；备份协议保留ExcelJS兼容入口。商品/销售文件改用本机受限子进程、流式ZIP/XML及会话SQLite，依赖版本见C13/D01；不增加前端框架。纯业务模块同时适用于Node校验与CSP限制下的浏览器，文件调度不另造业务状态。

### 4.1 工作区 v4

- 保留 `shops/plans/materials/sizes/shippingTemplates/records/prefs` 的正式结构。
- 新增 `pricingStrategies[]/sizeSchemes[]/promotionSchemes[]`，均有稳定 `id/name/deleted`。名称修剪、非空、最多80字符；同类型有效方案不能重名；删除项重名恢复时要求改名。原有 active 状态保留，选择条件统一 `active!==false && !deleted`。
- 现有三类资源增加 `deleted:false`，旧 `active:false` 仍表示停用，不自动转换成删除；厚度规则也保留稳定 ID，删除被引用规则需软删除，不允许悄悄改用默认厚度。
- `plan.strategyId=''`、`plan.promotionSchemeId=''`、`plan.salesSource=null`。尺寸组合是一次追加操作，不保存持续订阅的sizeSchemeId；编辑组合不会自动改已选规格。
- `item.id` 稳定且计划内唯一；`sizeId`不再唯一。增 `productId/skuId` 文本、`sales:null|非负整数`、`priceMode:'plan'|'manual'`，可选行 `materialId/materialRuleId` 覆盖。保留原 `price/share/weight`；重量内部一直 kg，界面 g。
- 旧行 ID 在 v3→v4 首次迁移中按原数组稳定分配，重试结果一致；不得把每次 render 的随机ID写回。复制计划分配新计划/行ID，不复制账目。
- 商品ID/SKU ID均trim后的字符串，不转Number；非空组合在计划内唯一，空ID可暂存等待绑定，禁止用“空串=同一SKU”合并。plan/item/resource引用不存在时报错，不能在sanitize中删字段蒙混通过。
- 定价列表参数最多100档；定价、尺寸组合、活动三类可复用方案每类合计最多20000份，尺寸方案每份最多5000个去重sizeId，活动最多10步；ID沿用1–100字符规则、绑定ID最多200字符，来源文件名/周期最多255/200字符。商品/销售源容量独立改按D02：压缩文件≤100MiB、所选sheet≤500000业务行/200列，不扩大正式计划SKU或资源上限。旧计划SKU沿用已验证的旧数据范围，不能因源文件容量而拒绝合法迁移。正式工作区20MiB按完整请求信封UTF-8字节计算，超限保留候选且不截断；备份仍走原协议预算，不套商品源限制，也不把工作区超限误报为备份损坏。
- 旧 SKU 默认继承计划材料/厚度，行明确选其他材料才覆盖。变更计划默认只影响继承行，不能覆盖行选择。缺少或删除的“已引用”规则不回退到另一成本。
- 旧材料确无厚度规则的合法计划保留`legacyCostFallback`兼容计算，避免升级后原可计算报价变成错误；与“已有规则被删除”严格区分。旧长名称、可选空尺寸名、特殊厚度ID的边界及首次配置迁移见合同C01。
- 客户端输入可保存不完整草稿（沿用 price/share 的空值语义），但非法数值、坏引用、未知策略类型不能入库；草稿不能入账或用于上架价结果。上限沿用现有20MiB完整请求信封、资源数量限制，所有新增数组和文本也纳入预算。
- 所有新增/编辑名称在领域层 trim 后检查非空，不仅依赖 HTML required。每个材料内厚度规则 ID 必须非空且唯一；ID兼容现有小数点，特殊旧ID仅映射live引用，具体见合同C01。所有提交统一 clone→校验候选→提交；不能像原型一样把无效状态先写入存储、下次启动才拒绝。

### 4.2 价格状态转换

采用“跟随计划/手动覆盖”两态，避免把所有旧行标成手动后，首次选策略完全无效。

| 操作 | 结果 |
|---|---|
| 旧版迁入/新建无策略行 | `priceMode=plan`、strategyId为空；显示手动价，原price不动 |
| 选择定价策略 | 只有plan行自动计算；已有manual行保留 |
| 用户在行内改售价 | 写price，改为manual；无论当前有无策略都记录为显式覆盖 |
| 点击恢复策略价 | 该行改为plan，使用当前方案；仅有方案时显示入口 |
| 全计划切回手动 | 先把plan行当前有效策略价存入price，再清strategyId；原manual不动；算不出的行留空并报错，不能拿旧缓存充当售价 |
| 再次选择方案 | plan行恢复自动，manual继续保留 |
| 材料、运费、策略参数变化 | 当前自动行重新计算；手动行价格不动、毛利和ROI按新成本更新 |

自动结果为纯派生值，不在 render 内写库。所有视图、Excel和快照都调用同一 `effectivePrice`/当前计算入口，禁止一个页面读取旧item.price缓存。新输入金额最多两位小数；旧版高精度price原值保留，活动计算器对该行提示需明确调整为分位，不擅自舍入旧售价。

## 5. 迁移、旧账、备份和删除

### 5.1 无损迁移

1. 冻结当前 v3 计算和旧Excel格式生成器为兼容模块，依赖旧的指标/列标签常量，不引用新文案。v1/v2仍走现有legacy路径再到v3，再升级v4。
2. `Store.upgrade` 在 `BEGIN IMMEDIATE` 内读取原始数据→按原版本验证→创建v4候选→验证候选→保留原始JSON recovery→一次提交并revision+1。失败回滚，revision/原JSON不变；重复启动不再次迁移。未知未来版本明确拒绝，不进入Legacy猜测。
3. 迁移全部live计划结构（包括已删除计划）及偏好。已有records及其frame/result不改写、不补随机ID、不重新定价。迁移后的第一次普通保存仍须通过冻结历史保护。
4. 新记录 `frame.calculationVersion=4`；旧frame无标记按v3计算。工作区v4的live计算使用新入口；历史v3查看/更正继续其原版本算法。保留现有legacy旧账验证。
5. `workspaceId/storageEpoch`保存在SQLite元信息；首次分配epoch=0，不随普通保存递增。成功整库恢复先经唯一FileJobBroker停止旧任务，再与工作区写入同事务递增epoch；同operationId重试不重复递增。旧文件会话保留供救援/重新复核，不自动附加到新epoch。迁移仅由服务端版本升级执行，普通PUT不接受客户端migration/restore reason；显式整库替换走独立POST /api/restore，见合同C02。旧客户端对已升级工作区的v3保存返回冲突/要求刷新；旧备份通过显式restore流程，先迁移再保存。
6. 相同版本的日常保存只验证，不隐式替换缺失规则或重写历史；前后端使用同一规范化候选。普通保存不做服务端规范化；迁移/恢复完成后以GET确认的新状态重建队列，不能只更新revision而继续持有坏引用。本次迁移保留所有现有运费引用，移除启动时按1.35元换模板的逻辑；不猜测某份固定运费是否应改区域模板。

### 5.2 冻结成本和入账

- `makeFrame`捕获全部被行引用的材料/厚度/尺寸/运费，把继承关系解析为明确行引用，最终到手价固化为数值；策略与活动只保存追溯所需快照，不对冻结售价重新应用。更正历史记录也不调用今日公共方案重新定价。新frame计算固定采用已存价格与成本；不能仅靠priceMode阻止重算，因为plan模式的冻结行也必须固定。
- 现有 `frame.materials[0]`、统一单价输入、按sizeId定位的入账/更正/明细/Excel全部排查。新多材料frame按“材料+厚度规则”显示实际成本，单材料仍保持紧凑布局；旧frame保持原表单兼容。历史成本更正只改本次副本。
- `confirmRecord`、Store历史保护、总账与趋势保持原语义，planId+date仅一条有效记录；更正/作废链完整，删除计划不影响累计。
- 冻结 result 按其计算版本检查必需字段完整性及对应金额，不能只遍历输入中存在的键。旧版合法可选字段按冻结兼容合同处理；缺少核心字段不能用当前规则重算并补写历史来通过校验。
- 包装重量：移除新界面手填项与相关提示；新计划不写统一包装系数。已有非零字段继续兼容计算，避免升级让现有报价跳变；旧快照完整保留，已有SKU实测weight优先。复制旧计划保留原兼容值，新加行仍遵循该旧计划规则；不把原有值悄悄清零。该兼容行为写入迁移说明，不新增手填系数入口。

### 5.3 删除与恢复

- 计划/六类资源/被引用厚度规则均软删除；资源实体、稳定ID、被引用数据保留。新选择不列出已删项，当前引用以“已删除”标记继续可算；离开后不能新选已删项。
- 禁止 `finalizeState/normalizeRules/initialize/newPlan`以“缺少活跃项”为由重建或自动换材料/运费。初次安装才创建内置资源，已有删除实体即代表用户选择。
- 全删材料/运费后，保留删除实体，创建计划/新增SKU给出前往规则库添加或恢复的空态，不偷偷采用第一个删除项。新建计划依赖不足时先补规则再建。
- 删除尺寸方案不移除计划SKU；删除尺寸定义不破坏已有SKU；选含已删尺寸的方案跳过未加入的已删尺寸并提示数量。尺寸方案只含sizeIds，重复选用幂等。
- 编辑已删规则前需恢复；修改仍在使用规则说明影响当前引用计划，不影响历史。恢复存在名称冲突则让该条改名，不覆盖同名方案。
- 所有规则编辑只在弹窗副本进行，保存时校验候选整体；取消不泄漏到当前计划。非法规则不能保存，合法规则与某计划费率组合不可定价时，该计划自动行明确报错、不能退回缓存旧价；历史和手动价格仍保留。

### 5.4 Excel、恢复与回滚

- 备份协议升为 `MAT-ROI-XLSX` format 5，workspace.version为4，两者分别管理。
- format1–4：原始JSON用旧版校验、原始可见页用冻结旧tables逐格核对，之后才 migrate→v4校验→范围校验。不能先迁移生成新表再核对旧表。旧格式只读兼容，新导出只写5。
- format5：可见页涵盖新规则、SKU ID/材料/模式/毛利/销量；隐藏恢复数据含完整新字段和删除状态。逐格防篡改继续保留，不能为通过旧表而取消验证。
- 完整备份保留全部规则，包括未使用与已删。范围备份收集被选计划的默认和行材料、厚度、运费、定价、活动及实际尺寸依赖闭包；尺寸组合没有持续计划引用，随完整备份迁移，不因包含某尺寸就自动夹入范围备份；历史frame自包含保持原样。不把未选计划的销售数据带入。
- 仅导出空店铺时允许资源数组为空（没有plan引用），不从state.materials[0]或运费[0]补一个已删除默认项。恢复后展示添加/恢复规则空态。v4校验以真实引用完整性判断，不再硬性要求空店铺也带材料/运费；旧格式校验仍保持旧合同。
- `transfer.merge`统一构建6类资源ID映射，先尺寸→尺寸方案，再计划和行引用；同ID不同内容建立新ID并重映射，同内容复用。厚度ID归属材料一起映射，重名按现有导入后缀机制处理。冻结frame的ID保持原样，不能映射到当下资源。
- 合并以计划为原子候选：有同日冲突或更正分支时不先写计划参数/规则再报错，失败计划保留本机数据，成功计划可按报告提交；二次导入幂等。默认不复活当前已删除方案/计划，显式恢复参数需在预览中说明。
- 当前工作区 JSON 校验失败时，仍能从启动错误页进入合法备份恢复。专用恢复事务先独立验证候选、读取原始revision并检查冲突，再保存旧原始JSON为恢复前原件，最后替换；不依赖 `Store.read()` 成功。坏备份/错revision/写盘失败均回滚。物理SQLite损坏另走离线恢复到隔离目录的流程，不承诺此接口修复损坏数据库文件。
- 回滚先停止应用并保全当前DB及WAL一致副本。程序回退必须配套“升级前恢复点”恢复到隔离目录检查，不能让旧程序直接写v4数据。升级后新账先备份，禁止直接覆盖丢弃；无法无损降级则保留数据修复新版本。

## 6. 定价与上架价格合同

### 6.1 三类定价

生产面积沿用正式 `productionArea`：规则矩形用销售尺寸、异形用实际生产尺寸。成本 C=材料成本+单次发货运费，平台费率f、税率t、目标毛利m按百分数换成小数。

`到手价 = 向上取分(C / (1-m-f-t))`

`实际毛利率 = (1-C/到手价-f-t) × 100%`

毛利不扣广告、退款、其他费用；这些仍按正式现有退款模型进入ROI/利润。定价用 `baseShipping`，不能误用已按未发货退款打折后的 `shipping`，也不能把正式每单总成本再次除费率造成重复扣费。

业务待核 BIZ01：现有 `recovery` 同时减少已发货仅退款与退货退款的商品成本，现有测试明确接受此公式，但界面称“退货回收比例”。已复现全部仅退款且回收100%时商品成本计0。当前施工保留旧口径；若用户确认仅退款不能回收货品，另立新计算版本用于新测算并更新验收，旧账不重算。不把这一业务判断混入定价或UI改名修复。

- 排名：本计划全部SKU按C四舍五入到分后的唯一成本升序密集排名，同成本同档；超出已设档用fallback。手动价SKU仍参与成本排序；有成本不明行则该策略自动行暂停并报错，防止悄悄挪档。
- 统一：每个自动SKU同目标毛利。
- 面积：按输入十进制精确分数计算`max(0,floor((area-baseArea)/stepArea))`，再将`baseMargin+档数×stepPoints`按cap截断；尺寸乘积/10000也按精确分数形成面积，算法与数值边界见合同C06。不先四舍五入面积，不用epsilon将真实未满档提升一档。低于基准不倒扣；+1/+2指百分点。stepArea>0，stepPoints>=0，cap>=baseMargin，全部有限。
- 校验分母必须>0，结果须为有效正金额；成本/重量不完整、运费超范围时显示具体SKU错误，不替换为0或旧价。不因订单占比暂未满100而阻止有效SKU显示策略报价，但阻止整体入账。
- 自动报价向上取分后反算毛利不得低于目标；所有策略参数/计算结果上限兼容现有数值限制。

### 6.2 活动方案和计算器

- 顺序有意义：每步基于前一步金额，整数分、四舍五入（半分进位）；折扣0.01–10折最多两位、直减0.01–1,000,000元最多两位，最多10步，减后最低0。未知类型包含满减必须拒绝。
- 逆序反推最低满足 `活动后金额 >= 目标到手价` 的上架分位。输出前再次正向验证，且低一分钱不应满足。按原型上限10^11分与safe integer检查，超限只报该行错误。
- 100→9折→减5=85；到手85对应最小上架100。改为减5→9折，到手85对应最小上架99.44；顺序调整必须更新明细与结果。
- 计算器只读当前有效到手价，不写SKU售价、策略、ROI或历史。计划仅保存所选活动ID；规则更新/改到手价时重算。无方案时按无活动价展示；异常行不伪造0元，Excel导出须先处理全部异常；本轮不新增单行排除导出功能。
- 保存/复制/另存活动在规则库，使用页最多保存当前已选方案副本（仅名称）及选用，不增活动细则入口。计算器关闭恢复触发按钮焦点，重开保留计划选择。
- 活动后金额允许因分位四舍五入高于目标，界面同时显示“预计到手价”和“高出目标”，不把高于目标的可行结果报错。上架价只是计算结果，不回写到商品转表的“平台售价”列，除非以后单独确认新需求。

## 7. 销售导入与商品转表

### 7.1 销售导入

- 原始文件只作为临时导入草稿，不塞进工作区JSON和每笔frame；保存每行销量、必要ID绑定与 `salesSource{filename,period,basis,total,excluded}`。
- `salesSource` 另存 `importId/appliedAt/missingPolicy` 用于幂等、撤销和审计；不保存本地绝对路径、原Excel或不必要的原始行。同一份草稿重复点应用只产生同一状态，不创建额外恢复快照。
- 旧SKU没有ID，必须提供首次导入绑定入口：唯一 `商品ID+SKU ID` 优先，SKU全计划唯一可匹配；无可靠ID时尺寸仅作候选。报表有未知ID不能因为尺寸一样就自动覆盖已有不同ID；明确选SKU后可保存绑定。
- 同尺寸不同商品/材质可存在多行，新item.id区分。所有表格改价、重量、移除、入账、销售匹配均使用item.id；旧历史按本地兼容定位，不修改旧frame。
- 导入会写入 `sales/share` 和来源；本轮销量列只读；之后用户手改任一行占比或SKU绑定时，保留 `salesSource` 供追溯但标记 `editedAfterImport:true`，并立即废弃本次一键撤销；不将手工数据还冒充为文件原值。再次导入则用新批次整体替换。
- 多数量列/多候选sheet需要选用，不能挑第一个混淆“支付订单数/件数”。件数需要明确按一单一件估算；销量为非负整数，空白、负值、NaN、超限阻止应用。
- 相同SKU多行在同次报表内汇总，重复导入整批替换；不同店铺、未匹配、歧义行先复核或明确排除。来源周期必须明确；不重写广告消耗或支付ROI。
- 数量本身及聚合总数须为safe integer且不超过现有MAX_VALUE。避免“大整数数量×10000”超精度：最大余数分配使用安全的整数/BigInt中间值，持久化仍普通JSON数字。非法或超限整批不能应用。
- 未覆盖全部SKU必须明确将未出现SKU按0处理才能重算全计划占比；总数0时不能重算或除0。正数占比使用最大余数法分配10000个基点，总和恰为100%，5000行也不会把尾行舍成负数。
- 最大余数法的同余数顺序固定为 `item.id` 升序，不依赖当前UI排序或Excel行序；否则同一批数据换个排序就会让若干SKU相差0.01%。基点只作为分配中间值，最终除100写回现有share百分数字段，不再保存第二个权威字段；旧浮点share原值保留，不因升级改变旧计划金额。
- 商品/销售源统一经过C09/C13文件会话，销售大表在后台先汇总到现有计划SKU，27万条明细不等于新增27万个计划SKU。导入预览绑定workspaceId/storageEpoch/shopId/planId及SKU指纹；切计划、SKU集合变化或第二次上传后，旧候选不能写到新页面。应用在最新工作区上只更新sales/share/必要绑定/source，保留期间新售价，经clone→验证→单次SaveQueue提交；失败不部分改数。
- 撤销仅恢复本次销售/占比/绑定字段，且只在该计划之后没有新编辑时可用；不能用整库快照覆盖其他计划后续操作。保存中禁重复应用，失败保留可重试草稿，revision冲突沿用现有解决流程。

### 7.2 商品转表识别与人工留空

- 保留正式字段映射、分组/分页复核和29列导出语义；文件读取按D02/D03流式上传及本机解析，容量为100MiB/500000业务行/200列，取代原15MiB/5000行路径。SKU描述列新增别名，长ID作为文本；数值型长ID、精确ID公式、错误单元格按D04待核，不能把已损失精度的ID静默恢复或匹配。
- 商品名称提炼材质，SKU描述/规格提取尺寸；材质采用最长词边界消歧，普通规格噪音不作为另一套材质自动匹配源，名称缺失或多候选进入复核。“伪亚麻”出现在相关原文任一处都必须人工选或明确留空，不能默认映射亚麻/硅藻泥。
- 尺寸识别显式成对的乘号、单位与可靠分隔；不再取任意前两个数字。`MZJ90-3;40*60cm`→40×60；`编号123 3mm 红色`→未识别；`400mm×60cm`→40×60；40×60/50×80→多候选。厚度不当宽长。
- 原文“宽×长”的顺序写入模板宽/长列，不在识别时自动把较小边当宽。当原文只能识别两个无语义方向的边，复核界面必须标明“第一边/第二边”并允许交换；交换不改面积/成本，但会改模板宽长列。
- 厚度识别区分原文未写、唯一明确、未知、多候选。先剔除已识别尺寸片段中的单位，再从名称、SKU描述、规格提取厚度；仅当当前已确认材质下存在唯一相符的有效规则时自动选用。原文未写、硅藻泥8mm等无对应规则、3/5mm冲突、重复厚度规则或不相符的包边变体均待人工确认；即使只有一个默认/标准规则也不能静默套用。材质/尺寸明确blank时按依赖清空合同处理。
- 材质与尺寸各自 `pending/value/blank`。批量patch采用keep/value/blank三种操作，undefined=不动，blank=人工确认留空；全选、按商品分组、applyReviews、导出前复算全部遵守同一合同。
- 每次复算先清除派生字段：材质blank保留有效宽长/面积，重量成本为空；尺寸blank清尺寸/面积/重量/成本，材质保留；两个blank允许导出。若尺寸明确为空，不能因没有可计算重量而再次阻拦；若仍需计算且厚度/成本有歧义才待复核。
- 已填值无效不能冒充blank；商品ID、SKU ID、名称、规格、店铺、状态及售价库存等现有校验继续，不因允许材质/尺寸空而放宽其他必需字段。
- 原始名称/规格独立保存，只重建程序追加的材质后缀；清空或换材质不叠加旧后缀，不删除用户原文。
- 正式导出器按D08保留受控模板部件，流式替换sheetData并更新dimension/autoFilter，取代ExcelJS整本加载和逐尾行删除的实现要求；G62无残留、29列、文本ID、样式、冻结和过滤范围仍是必须结果。新留空写真实空单元格，旧导出器留作小样本对照，不能复制原型只拷少量样式的导出器。
- 工作区规则显式传给转表模块，不能与内置默认材料自动合并；只在无工作区配置的独立旧接口使用旧默认规则。已删除材料不参与新识别，已有人工确认引用保留快照/标记，不暗换。
- 转表复核状态采用稳定materialId/ruleId而不是名称作引用；保留原始名称与展示快照。改名更新展示，改成本/系数使派生值失效重算，软删除按原引用保留并标记；缺失实体明确报错。商品级/逐行复核决定保存于C09转表会话草稿，导航、分页和异步重绘不丢输入；不塞入业务工作区或历史frame。
- 预览与导出共用唯一纯行函数deriveTransferRow及不可变规则快照，后台分批写derivedGeneration，页面仅取100行。全表ready与规则指纹通过后冻结导出版本；下载开始前再次核对，不能用旧rules缓存金额。导出已开始发送后属于已交付快照，后续规则变化不撤回已发送字节。
- 规则变化后转表草稿标记为已过期并重算。若材料改名、成本/系数修改且稳定ID仍存在，保留人工选择；若已确认引用被软删除，保留原引用继续计算并标记；实体实际丢失则保留痕迹并待复核；auto新识别不选已删项，不自动选同名/默认材料。导出交付前若相关规则指纹已变，丢弃该文件并要求用新版本重算，不让旧任务完成后覆盖新预览。
- 完整上传后按ZIP关系定位sheet并有界读取前40个物理行表头，多个候选供选用；仅所选sheet扫描业务数据并受500000行/200列限制，无关sheet不按业务行数拒绝，但整个ZIP仍受D02资源预算。格式化空行不计业务行，不按dimension预分配数组。

### 7.3 已确认的转表界面与操作（2026-09-19）

本节按用户对独立原型 rev=3–9 的逐次修订及本次补录指令收口。原先“缺失默认厚度/全部人工模式”的方案选择已被下列筛选与批处理流程替代；不保留转表顶部方案选择、保存方案、厚度模式面板或规则库中的“识别与确认方案”。材料、厚度、重量系数与成本的真实规则仍在“可复用规则”编辑，定价、尺寸、活动等既定方案照常保留。

- **三字段同级**：表格、逐行选择及原有“批量处理所选”弹窗并列提供材质、厚度、尺寸。保留原有批量能力；顶部不再另加三个字段批量按钮、重复规则库快捷入口或重置示例入口。材质与尺寸支持明确“保留为空”；厚度选择已有材料规则，不新增厚度留空以绕过重量成本计算。
- **筛选展开**：收起时为“全部规格 / 待复核 / 已确认 / 更多筛选”；展开时顺序严格为“全部规格 / 待复核 / 已确认 / 未写厚度 / ‹”。“更多筛选”文字让位，收起箭头在新增选项之后、筛选组最右侧；新增选项沿用左侧按钮样式，不用复选框、弹窗或向下独立面板。窄屏可换行，“未写厚度”与其后的箭头保持同组、同一行，键盘顺序与视觉顺序一致。
- **筛选含义**：“未写厚度”根据不可变原文候选为空判断；未知8mm、多个厚度均不命中。人工填厚度后仍命中，可结合“待复核”只看未完成行。状态计数在当前厚度条件内统计，“未写厚度”数字统计整个导入会话；收起不清除已选条件，触发器选中态和提示说明条件仍有效，展开后可取消。刷新/重开筛选默认复位，已确认的字段草稿保留。
- **商品行**：按完整平台、店铺、商品ID分组，缺少任一身份逐行隔离；商品ID后小字“同链接批量处理”。超过10个字符显示前6位、省略号、后4位，完整ID保留在提示、辅助标签、分组和导出中；平台/店铺放在范围提示里区分同ID。缺身份行说明仅作用本行，不暗示可靠同链接分组。
- **同链接下拉**：ID行的材质、厚度下拉分别对齐表格对应列；直接统一该商品全部SKU的所选字段，含已确认、筛选隐藏及分页隐藏行。行上显示总数和隐藏数，控件提示写明全组范围。尺寸保持逐行原值，不在商品行增加统一尺寸或另一批量按钮。
- **依赖保护**：组内材质不一致或未确认时，组厚度禁用，先统一材质；材质留空或全部尺寸留空时不需厚度，部分尺寸留空只处理其余行。实际切换材质ID清旧厚度并待人工确认，不因原文厚度恰能匹配新材质而自动恢复；确认同一材质不无故清厚度，材料改名也不算切换材质。
- **勾选批量**：全选和商品组勾选只选当前页、当前筛选可见的SKU；筛选、翻页或行修改后剔除隐藏选择，再次显示不复活旧勾选。弹窗沿用一处“批量处理所选”，三个字段默认“保持原值”；仅修改所选字段的待确认项，显式勾选覆盖才改已确认值（含自动值、手动值和留空）。尺寸可选已有尺寸或输入本次宽长，预览实际更新数、受保护及厚度不匹配数。
- **失败与撤销**：预览与提交共用逐行候选校验；组级大操作分批准备、事务发布，非法输入不部分写入，无变化不提示成功。同链接直改的最近一次撤销仅恢复受影响字段；后续数据/规则变化使其失效，单纯筛选不失效。事务成功才称复核已保留，失败保留未提交输入；响应不明先查mutationId回执，不盲目重放。浏览器缓存失败不改变已落盘复核；见C07/C09。
- **导出**：始终校验全部导入行，不能因筛选只剩已确认行或空列表放开导出。保留真实Excel读入、29列模板、文本ID、G62无公式残留结果及独立留空合同；不把独立原型的CSV或完整原型的简化导出器替换正式模板导出。
